## Purpose

定义挂载生命周期的两个可见性契约：挂载失败后过程日志必须可查；应用以管理员运行时必须就"挂载盘符对桌面不可见"给出警告。

## ADDED Requirements

### Requirement: 挂载失败后日志可查

挂载过程（连接发起、失败原因、等待结果）的日志 MUST 在挂载失败后仍可通过状态查询接口获取，供界面日志面板展示；同一驱动器重新发起挂载或挂载成功后，上一轮失败日志 MUST 被清除。

#### Scenario: 挂载点被占用导致失败

- **WHEN** 用户发起挂载且 WinFsp 报告挂载点已被占用
- **THEN** 该驱动器的状态查询返回 `mounted=false`，且日志内容包含本次挂载的发起记录与失败原因（不再是空白）

#### Scenario: 等待挂载就绪超时

- **WHEN** 挂载调用后盘符在超时窗口内未就绪
- **THEN** 挂载以失败结束，且日志内容包含"开始挂载"与"超时未就绪"的记录

#### Scenario: 失败后重新挂载

- **WHEN** 挂载失败后用户再次对同一驱动器发起挂载
- **THEN** 上一轮失败日志被清除，日志面板展示新一轮挂载的过程记录

### Requirement: 提权运行时警告盘符不可见

应用以管理员（提权）身份运行时，启动阶段 MUST 向用户发出警告，说明管理员运行的挂载盘符对桌面会话不可见并建议以普通权限重启；非提权运行时 MUST NOT 出现该警告。应用 MUST NOT 因提权而拒绝执行挂载。

#### Scenario: 管理员运行启动应用

- **WHEN** 应用进程以提升的 token 启动
- **THEN** 出现一次系统托盘警告通知，文案包含"以普通权限重新启动"的建议

#### Scenario: 普通权限运行启动应用

- **WHEN** 应用进程以普通 token 启动
- **THEN** 不出现提权警告
